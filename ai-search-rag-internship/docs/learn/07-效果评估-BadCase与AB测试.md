# 07 效果评估 · BadCase 与 A/B 测试

> 能力域：效果评估 ｜ 对应简历（产品岗）："梳理2万条搜索日志提炼3类痛点，零结果率下降52%；Query改写长尾词转化+18%；组织3名标注员完成200条QA标注"

## 0 企业案例与用户故事

**2 万条搜索日志里挖出的 3 个真相**

传习智学上线后，数据产品同学（"我"）拉出 2 万条搜索日志做 Bad Case 分析。把"用户搜了什么 → 系统给了什么 → 用户点没点 / 买没买"摊开看，问题浮出水面：

| 痛点 | 用户怎么说 | 系统做了什么 | 占比 |
| --- | --- | --- | --- |
| 自然语言找货 | "想找适合露营的轻便保温杯，别太贵" | 词面不匹配，返回无关资源 | ~31% |
| 属性模糊匹配 | "蓝牙耳机 降噪 通勤 续航久" | 只命中"蓝牙耳机"，属性排序错 | ~27% |
| 精确编号找不到 | "人教A版必修二导数教案" | 精确编号/版本被语义召回稀释 | ~22% |

三个现象对应同一批用户行为：**用户搜不到 → 改口再搜 → 搜不到就走**。改口再搜的用户就是"query reformulation"，是检索失败最直接的信号。

团队据此拆需求：先上 Query 改写（痛点①②），再调精确词召回（痛点③）。上线后**对应场景零结果率下降 52%**；跑 A/B 又发现 **Query 改写对长尾词的转化提升 +18%**。

但在写"A/B 证明有效"之前，我碰到了一个坑：**直接比较两个版本的 CTR 是错的**。

```text
业务痛点：检索失败没有分类、上线效果没有受控验证
技术问题：Bad Case 分类 + A/B 测试（含统计陷阱）+ 人工评测流程
业务指标：零结果率 / CTR / CVR / reformulation rate / 标注一致性
```

## 1 原理直觉

### 1.1 Bad Case 先分类，才能对症下药

把失败 Query 结构化分类（来自搜索日志 + 人工标注）：

```text
Bad Case
├── 语义不理解（用户表达与文案词汇鸿沟）
├── 属性匹配错误（同族商品、属性排错）
├── 品牌/版本匹配错误（精确编号被稀释）
├── 型号/教材编号匹配错误
├── 无结果（零召回）
└── 排序错误（对的结果有，但排太后）
```

每一类对应不同解法：语义→Dense/Hybrid；属性→Query 改写/字段索引；精确编号→BM25 加权/Query 分类器；无结果→扩召回/纠错；排序→Rerank。**没有分类，2 万条日志只是一堆"用户不满意"。**

### 1.2 搜索 A/B 和按钮 A/B 不是一回事

传统 A/B 假设"对照组和治疗组静态独立"。但**搜索/推荐模型会从行为数据学习**：用户点击会回流进训练信号。三件基础设施要求：

1. **一致的 user bucketing**：同一用户始终分到同一组（跨 session 一致）。
2. **每个事件日志都带 experiment ID**：否则无法归因点击/转化来自哪组，模型训练也会用错信号。
3. **组隔离发生在模型训练层**，不只是 UI 层。

还有一个"治疗组不是一个固定东西"的问题：**AI 搜索在实验期间也在变**（模型被行为数据更新），周二和周五的"治疗"不是同一个。

### 1.3 为什么不能直接比两个版本的 CTR

1. **Goodhart's Law**：CTR 当目标就成了坏指标——标题党/刺激性结果点击高但转化低。
2. **novelty 效应**：新界面刚上线用户爱点，前两周数据"撒谎"；至少跑 2~4 周。
3. **多指标假阳性叠加**：5 个指标都按 5% 显著性，至少一个假阳性的概率约 41%；要 pre-register 指标 + 多重比较校正（Bonferroni / Benjamini-Hochberg）。
4. **样本量不足**：转化是低频高方差事件，按按钮测试算出的样本量会严重低估需求；可用 CUPED 用实验前数据降方差。
5. **SRM（Sample Ratio Mismatch）**：48/52 的分流说明事件日志有洞，结果不可信。

**正确姿势**：主指标选"和任务完成直接相关"的（购买/加购/零结果率/二次搜索），CTR/dwell 只当 engagement 信号，**零结果率当 guardrail**——即使主指标涨了，零结果率恶化就该叫停。

### 1.4 四级评估栈：离线 → 人工 → 影子 → 线上

| 层 | 问题 | 规模 |
| --- | --- | --- |
| 离线指标 | 候选值不值得继续做？ | 万~百万级 query-doc |
| 并排人工评测 | 哪个排序列表更满足意图？ | 500~5000 Query |
| 影子流量 | 线上能跑、不超延迟预算吗？ | 1%~10% 镜像 |
| 线上 A/B | 哪个版本改善用户结果？ | 2~4 周线上 |

分层推进：**离线筛掉弱候选 → 人工找可见缺陷 → 影子测运行约束（p95<150ms / p99<300ms 常见目标）→ 线上测真实行为**。跳过任何一层都可能让有缺陷的模型上线。

### 1.5 人工评测怎么做才可信

- 统一 rubric（不是让标注员自由发挥），标"winner + failure mode"。
- 3 名标注员 200 条 QA，**算一致性**（如 Cohen's kappa）；一致率 30% 以下说明 rubric 或意图定义要重做。
- 严重失败（权限泄露、错误医疗建议）不平均掉，单独卡上线。
- 用"共同+对抗性"Query：常见 Query 验日常质量，对抗 Query（拼写错、旧名称、歧义医学词）验边界。

## 2 最小实验

### 2.1 Bad Case 分类实验（复用已有数据）

本仓库 `docs/phase2-product-bm25-baseline.md` 已有一个现成 Bad Case：

```text
Query: 想找无线耳机，用于通勤，重点是充一次电用很久
现象: BM25 找到了"降噪蓝牙耳机"商品族，但把"入耳舒适"桶排在"长续航"桶前面
归类: 属性匹配错误（属性别名问题，rewrite/Dense 可解）
```

练习：把 50 条 qrels 的零召回 Query 逐一归类到 1.1 的分类树，输出一张分类表。

### 2.2 设计一份可执行的 A/B 计划（模板已备）

模板：`docs/templates/AB_test_plan.md`。要点：

```text
假设：Query 改写上线后，长尾 Query 的零结果率下降、转化提升
分流单元：user_id（确定性 hash）
组隔离：模型训练层也按组隔离，事件日志带 experiment_id
主指标：长尾 Query 零结果率、CVR
guardrail：整体 CTR 不回退、p95 延迟 <150ms、SRM 检测
运行时长：≥2 周（覆盖工作日+周末，熬过 novelty）
样本量：按转化事件做 power analysis，必要时 CUPED
```

### 2.3 人工评测 SOP（对齐简历"3 名标注员 200 条 QA"）

```text
1. 定 rubric：什么是"正确回答"、什么算"部分正确"、失败模式枚举
2. 抽样：覆盖单跳/多跳/不可回答、4 个业务领域
3. 双人标注 + 第三人裁决分歧；记录一致率
4. 输出周度报告：按领域/问题类型分组，定位短板（如"多跳问题"）
```

**口径红线**：本仓库是合成教学数据，**没有真实线上 CTR/CVR**。这些"52%/-18%"要么来自真实实习记录（你确实做过），要么写成"离线 qrels 上的等价结论 + A/B 方案"，不要伪造线上数字。

## 4 面试深挖

**Q1：为什么不能直接比较两个版本的 CTR？**
CTR 是 engagement 代理指标不是成功指标（标题党刷点击）；novelty 效应让新版本前期数据虚高；多指标显著性叠加产生假阳性；转化事件低频高方差需要比按钮测试大得多的样本。正确做法：pre-register 指标、跑满 2~4 周、多重比较校正、零结果率当 guardrail。

**Q2：novelty 效应是什么？怎么处理？**
用户对"新"的探索行为抬升早期 engagement。处理：跑足时长（2~4 周）等衰减，或只用新用户。

**Q3：零结果率为什么是 guardrail 而不是主指标？**
它是最直接的检索失败信号，且容易恶化但主指标未必立刻反映。一个"点击变多但零结果也变多"的版本可能是靠标题党拉动，应该叫停。

**Q4：搜索 A/B 和普通按钮 A/B 的本质区别？**
治疗组会随行为数据学习而改变、两组会互相污染；所以必须 experiment ID 全量打点、组隔离到训练层、bucketing 确定性一致。

**Q5：Bad Case 分类对产品/算法分别有什么用？**
对算法：每类对应技术方案（Dense/Hybrid/rewrite/rerank）；对产品：变成需求优先级（高频痛点先做）+ 上线指标（零结果率）。

**Q6：3 名标注员的结果怎么保证一致可信？**
统一 rubric + 失败模式枚举；双人标注第三人裁决；算一致率（30% 以下先修 rubric 再标）；严重失败单独卡上线不平均掉。
