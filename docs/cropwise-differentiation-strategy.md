# CropWise 差异化战略与执行路线

## 结论先行

CropWise 不应与通用聊天机器人比“谁更会生成长答案”，而应成为江西种植者和农技人员的“可追溯田间决策工作台”。差异化核心是：

> **把一条模糊问题，转成带地区、生育期、症状、证据、风险和复查节点的农业行动方案。**

这条路线把江农品牌、农业知识库和真实农事流程连接起来，形成比“农业版 ChatGPT”更难复制的产品认知。

## 研究依据

以下资料用于确定产品方向，优先选择政策机构、研究论文和可复核的官方来源：

1. [FAO Digital Agriculture](https://www.fao.org/digital-agriculture/en/)：数字农业服务需要围绕农户决策、可达性、数据和本地生态建设，而不只是增加信息量。
2. [World Bank · Digital Agriculture](https://www.worldbank.org/en/topic/agriculture/brief/digital-agriculture)：数字技术的价值在于改善小农户获得信息、市场和服务的能力，信任、基础设施和本地适配是采用前提。
3. [农业农村部与数字乡村相关政策](https://www.gov.cn/zhengce/2024-02/03/content_6929935.htm)：农业数字化应服务生产经营、风险管理和乡村治理，产品需要连接实际业务闭环。
4. [Ragas: Automated Evaluation of Retrieval Augmented Generation](https://arxiv.org/abs/2309.15217)：RAG 应分别评估检索相关性、忠实度和回答质量，不能用“看起来通顺”代替效果验证。
5. [GraphRAG: From Local to Global](https://arxiv.org/abs/2404.16130)：复杂农业问题往往跨作物、时序、地区和因果关系，结构化上下文比单次相似度检索更有潜力。
6. [江西农业大学官网](https://www.jxau.edu.cn/)：江农的科研成果、区域优势和农科教育资源是 CropWise 可以合法、真实、持续沉淀的内容资产。

## 竞品同质化的根因

大多数农业 AI 产品容易落入以下模式：

- 一个聊天框 + 一段通用回答；
- “支持图片识别、语音、天气、价格”的功能罗列，但没有完整决策链；
- 来源只显示“AI 生成”或一组无法判断可信度的链接；
- 面向全国的泛化答案，没有省域、县域、品种、农时和登记信息上下文；
- 只做首次问答，不沉淀病例、复查结果和失败案例。

CropWise 的竞争策略应避开同一赛道的功能堆叠，优先占领“可信、可执行、可复查”的窄场景。

## 产品楔子：田间决策卡

每个问题都尽量形成一张“田间决策卡”：

1. **现场摘要**：作物、品种、地区、生育期、天气/灌溉、症状起始时间和影响范围。
2. **优先判断**：按可能性列出 2-3 个原因，并说明依据，而不是直接给单一确诊。
3. **现在做什么**：今天、48 小时内、本生育阶段的动作清单。
4. **用量与边界**：涉及农药、肥料时，展示登记、说明书、安全间隔和当地农技站复核提醒。
5. **证据层**：区分知识库原文、官方资料、模型一般建议；展示来源标题、更新时间和匹配度。
6. **复查节点**：建议用户在何时回传结果，形成“建议 → 执行 → 复查”的闭环。

当前版本已经落地第一步的“田间简报”入口和知识库匹配度展示，后续应把回答协议继续结构化。

## 四个长期护城河

### 1. 地域化知识图谱

以江西为默认区域，逐步建立“县域 - 作物 - 品种 - 生育期 - 病虫害 - 农时 - 官方政策”的关系。不要一次性追求全国覆盖，先做江西水稻、油菜、蔬菜和果树的高质量闭环。

### 2. 证据与评测系统

每次回答记录：问题分类、召回文档、距离/匹配度、引用覆盖、用户是否采纳、复查结果。建立至少 100 条人工标注测试集，按检索相关性、答案忠实度、行动完整度和领域边界分别评分。

### 3. 农技人员协同

设置“提交农技站复核”“标记为疑难病例”“引用江农科研成果”路径。AI 不替代专家，而是把信息整理成专家可以快速接手的简报。

### 4. 决策记忆而非聊天记忆

普通会话记忆只保存文本；CropWise 应保存田块/作物档案、已采取措施、复查结果和季节时间线。用户再次提问时，系统能回答“上次处理后有没有改善”，而不只是复述历史。

## 优先级路线

### P0：现在完成

- 田间简报输入（已实现）；
- 知识上下文匹配度（已实现）；
- 明确区分“知识库依据 / 一般建议 / 官方资源”；
- 回答末尾增加“下一步动作 + 复查时间 + 需要升级的信号”；
- 记录每次检索和用户反馈，作为评测数据。

### P1：下一轮

- 决策卡 UI：摘要、判断、行动、风险、复查五段式；
- 江西农时日历与县域筛选；
- 病虫害图片上传，先做“辅助鉴别”而非自动确诊；
- 来源详情抽屉：原文片段、来源机构、更新时间、访问链接；
- “有帮助 / 不准确 / 需要专家”三态反馈。

### P2：形成壁垒

- 作物档案和田块时间线；
- 农技站协同工作台；
- 基于复查结果的病例库；
- RAG 评测仪表盘和回归测试；
- 将江农公开科研成果转化为可引用的技术卡和教学内容。

## 不建议优先做的功能

- 没有数据闭环的泛语音助手；
- 只展示天气或价格的装饰型小组件；
- 未建立审核链路前的自动农药处方；
- 没有真实用户需求支撑的复杂 3D/动效；
- 只追求更长、更像专家的回答。

## 核心指标

### 用户价值

- 首次问题中包含作物、地区、生育期、症状的比例；
- 建议被用户标记“可执行”的比例；
- 复查回访率和问题解决率；
- 从首次提问到形成可执行方案的时间。

### 可信度

- 有知识库证据的回答比例；
- 引用覆盖率和引用点击率；
- 检索相关性、回答忠实度、领域越界率；
- 农药/肥料相关回答的安全提醒覆盖率。

### 产品护城河

- 有复查结果的病例数；
- 江西县域/作物/生育期覆盖度；
- 农技人员复核或采纳的建议数；
- 经过人工标注的高质量评测样本数。

## 90 天执行建议

1. **第 1-2 周**：完成决策卡回答协议、来源字段、反馈事件和 100 条评测集。
2. **第 3-6 周**：完成江西水稻专题、农时日历、来源抽屉和复查提醒。
3. **第 7-10 周**：完成图片辅助鉴别、病例时间线和农技站转交格式。
4. **第 11-13 周**：用真实测试问题进行离线评测和小范围试用，依据数据调整召回、提示词和 UI。

## 最终定位

CropWise 的一句话定位应从“农业智能问答”升级为：

> **江西农业大学 CropWise：把田间观察变成有依据、能执行、可复查的农业决策。**
