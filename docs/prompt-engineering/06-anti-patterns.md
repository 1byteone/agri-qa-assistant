# 06 常见错误与反模式

## 6.1 指令层面

| 反模式 | 问题 | 修正 |
|--------|------|------|
| 模糊指令 | "写点东西" | "写一篇 500 字的博客文章，关于远程工作效率" |
| 否定式指令 | "不要太技术化" | "使用面向普通读者的语言，避免专业术语" |
| 过度复杂 | 一个 Prompt 塞入 10 个任务 | 拆分为 Prompt Chain 或 Agent Workflow |
| 缺乏上下文 | 直接要求分析未知数据 | 先提供数据来源、业务背景、受众信息 |
| 无格式约束 | "返回结果" | "以 JSON 格式返回，包含 title、summary、tags 字段" |

## 6.2 示例层面

| 反模式 | 问题 | 修正 |
|--------|------|------|
| 示例质量差 | 输出格式、风格不符合要求 | 示例必须与目标输出严格一致 |
| 示例顺序固定 | 导致 recency bias / majority bias | 随机化顺序，均衡标签分布 |
| 示例过多 | Token 浪费，可能引入噪声 | 2-3 个高质量示例通常足够 |
| 示例过时 | 使用旧版 API / 语法 | 定期更新示例，与生产环境同步 |

## 6.3 结构层面

| 反模式 | 问题 | 修正 |
|--------|------|------|
| 一大段文本 | 模型难以区分指令、上下文、输入 | 用 Markdown 标题 + XML 标签分段 |
| 关键信息后置 | 模型注意力衰减 | 最重要的指令和背景放在最前 |
| 缺少分隔符 | 模型混淆指令与数据 | 用 `"""`、`<context>...</context>` 明确边界 |

## 6.4 模型利用层面

| 反模式 | 问题 | 修正 |
|--------|------|------|
| 对 GPT 类模型用高 Temperature | 输出不稳定 | 确定性任务用 0-0.2，创意任务可调高 |
| 对 Reasoning 模型过度指令 | 抑制其自主推理 | 给高层目标，而非详细步骤 |
| 超长上下文塞满无关内容 | 噪声干扰 + 成本飙升 | RAG 筛选最相关片段 |
| 忽视 Prompt Caching | Token 浪费 | 静态内容前置，利用缓存 |

## 6.5 工程实践层面

| 反模式 | 问题 | 修正 |
|--------|------|------|
| Prompt 硬编码在聊天窗口 | 不可版本化、不可测试 | 存入代码库，纳入 CI/CD |
| 无评估集 | 迭代靠感觉，无法量化改进 | 建立 10-50 cases 的回归测试集 |
| 不测试边界情况 | 上线后才发现 failure mode | 主动构造异常输入、对抗样本 |
| 忽视 Token 预算 | 超出上下文窗口或成本失控 | 设计时预估 Token 消耗，设置硬限制 |
| 一次改太多 | 无法定位哪次改动有效 | 单变量原则，每次只改一个假设 |

## 6.6 幻觉与事实性问题

| 反模式 | 问题 | 修正 |
|--------|------|------|
| 完全依赖模型记忆 | 事实错误、过时信息 | 接入 RAG 或实时搜索 |
| 不要求引用来源 | 无法验证 | 要求模型标注信息来源段落 |
| 对不确定问题放任 | 模型编造答案 | 要求 "If unsure, say I don't know" |
| 无事实校验层 | 幻觉直接输出给用户 | 增加检索验证或 LLM-as-judge |

## 6.7 安全检查清单

在将任何 Prompt 上线前，问自己：

- [ ] 是否避免了模糊/否定指令？
- [ ] 是否有清晰的角色、任务、格式定义？
- [ ] 示例是否与目标输出一致？
- [ ] 是否限制了 Token 长度，防止 runaway？
- [ ] 是否有安全护栏（禁止内容清单）？
- [ ] 是否要求模型在不确定时拒绝回答？
- [ ] 是否已在小范围测试集上验证？
- [ ] 是否有回退策略（模型输出异常时的降级方案）？

## 6.8 练习题与自检

### 练习题 1：重构弱 Prompt

**原始 Prompt**：
```
写一个关于人工智能的文章。
```

**任务**：用 ICIO 框架重构这个 Prompt，使其更具体、可执行。

<details>
<summary>参考答案</summary>

```
# Role
你是一位科技专栏作家，擅长将复杂技术概念转化为通俗易懂的文章。

# Context
目标读者：25-40 岁的科技爱好者，有一定技术背景但不是专家。
文章将发布在 Medium 上，需要吸引点击和分享。

# Task
写一篇关于"人工智能如何改变日常办公"的深度文章。

# Format
- 字数：800-1200 字
- 结构：标题 + 引言 + 3 个具体案例 + 结论
- 风格：专业但亲切，避免过度技术化
- 每段不超过 150 字

# Examples
引言示例：
"2024 年的一个普通工作日，你的 AI 助手已经帮你处理了 80% 的邮件..."
```

</details>

### 练习题 2：识别反模式

以下 Prompt 存在哪些问题？请列出至少 3 个。

```
Prompt：
你是一个专家。帮我分析一下这个数据：[1000 行 CSV 数据]。不要太长，也不要太短。
给我一些建议，不要用太专业的术语。
```

<details>
<summary>参考答案</summary>

1. **角色模糊**："专家"未指明领域（数据分析？业务？统计？）
2. **否定式指令**："不要太长"应改为"控制在 500 字以内"
3. **上下文缺失**：未说明数据来源、业务背景、分析目的
4. **格式缺失**：未指定输出结构（列表？段落？表格？）
5. **超长输入**：1000 行 CSV 直接塞入 Prompt，应使用 RAG 或摘要
6. **模糊约束**："不要太专业"应改为"面向非技术背景的运营人员"

</details>

### 练习题 3：选择合适的技术

针对以下场景，选择最合适的 Prompt Engineering 技术：

1. 客服系统中，用户问题类型多样（退款、技术、咨询），需要分发给不同的处理流程。
2. 需要模型对复杂数学题进行推理，要求展示步骤。
3. 公司内部知识库问答，需要回答员工关于政策的问题。
4. 需要生成高质量的营销文案，每次生成多个版本供选择。

<details>
<summary>参考答案</summary>

1. **Routing**：先分类用户意图，再分发到专用 Prompt
2. **CoT（Chain-of-Thought）**：要求模型逐步推理
3. **RAG**：检索内部知识库片段注入 Prompt
4. **Parallelization（Voting）**：多次生成，选择最优版本

</details>

### 练习题 4：设计 System Prompt

为以下场景设计一个完整的 System Prompt：

- **场景**：编程助教机器人
- **受众**：编程初学者（18-25 岁大学生）
- **能力**：解释概念、debug 代码、给出学习建议
- **约束**：不要直接给出答案，要引导思考；不要用过于专业的术语

<details>
<summary>参考答案</summary>

```
# Identity
你是一位耐心、鼓励式的编程助教，擅长帮助大学生理解编程概念。
你的教学风格：苏格拉底式提问，用类比解释抽象概念，庆祝小进步。

# Target Audience
18-25 岁大学生，编程初学者。
- 已掌握基础语法（变量、循环、条件）
- 正在学习数据结构和算法
- 容易因报错信息而气馁

# Capabilities
1. 解释概念：用生活类比 + 代码示例
2. Debug 帮助：引导学生自己发现错误，不直接给答案
3. 学习建议：推荐练习顺序和学习资源

# Constraints
-  NEVER 直接给出完整答案
-  NEVER 使用未解释的专业术语
-  NEVER 说"这很简单"或"你应该已经会了"
-  ALWAYS 先肯定学生的努力，再指出改进方向
-  ALWAYS 提供 1-2 个提示性问题引导学生思考

# Format
- 代码用代码块 + 语法高亮
- 关键概念用 **粗体** 强调
- 复杂概念提供 1 个生活类比
- 每次回复不超过 200 字（除非学生要求详细解释）

# Tone
耐心、鼓励、专业但亲切。
```
</details>

### 自检清单：我的 Prompt 合格吗？

完成一个 Prompt 后，用以下清单快速检查：

**结构检查**
- [ ] 有明确的角色定义
- [ ] 有清晰的输入/输出格式
- [ ] 有至少 1 个示例（复杂任务）

**质量检查**
- [ ] 指令是正面的（不说"不要"，说"要"）
- [ ] 约束是可量化的（"500 字"而非"不要太长"）
- [ ] 关键信息前置（最重要的放在最前面）

**技术检查**
- [ ] 已指定合适的模型
- [ ] 已设置合理的 temperature
- [ ] Token 预算在上下文窗口内

**安全检查**
- [ ] 有安全护栏（禁止内容清单）
- [ ] 要求模型在不确定时拒绝回答
- [ ] 无 PII 泄露风险

**工程检查**
- [ ] Prompt 已存入代码库
- [ ] 有对应的测试用例
- [ ] 有评估标准和回归测试集
