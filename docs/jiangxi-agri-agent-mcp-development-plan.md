# CropWise 江西农业 AI Agent / MCP 开发计划

**版本**：0.1（架构与交付基线）  
**日期**：2026-08-09  
**适用项目**：江西农业大学 CropWise 农业知识问答系统  
**目标**：把现有农业问答原型升级为“有江西语境、有证据链、可执行、可复查、可扩展 MCP 的农业决策服务”。

## 1. 执行摘要

本项目不建议立即把所有服务替换为 Dify、RAGFlow、Milvus 或外部 MCP。当前系统已经具备 Agent 工具循环、Chroma 本地向量库、农业领域约束、SSE 流式 UI、会话记忆和资源卡片。最小返工路线是：

1. 保留现有 `agent.py`、`knowledge_base.py`、`tools.py` 和 `/chat/stream`，先统一工具输入输出契约。
2. 先做“内嵌适配器”，再为稳定能力提供标准 MCP Server；Agent 通过同一套 `ToolResult` 消费两者。
3. 先做江西高频且可验证的水稻、油菜、赣南脐橙和蔬菜场景，再扩展畜禽、水产、茶叶和中药材。
4. 先把官方资料、县域农时、气象和 RAG 证据做可靠，再接遥感、土壤、市场和图像模型。

## 1.1 江农特色适配基线（已确认）

本项目的“江西农业”不是泛化的全国农业问答，而是以江西农业大学公开办学与科研定位为锚点。江农官网学校简介（更新时间：2026 年 6 月）明确提出“以农为优势、以生物技术为特色”，并说明学校形成了家猪、水稻、生物多样性保护等优势领域；科学研究栏目公开列出猪遗传改良、水稻工程、鄱阳湖流域农业资源与生态、果蔬保鲜与无损检测、动物营养、畜禽疫病诊断、现代农业装备等科研平台。

官方依据：

- [江西农业大学学校简介](https://www.jxau.edu.cn/xqzl/xxjj.htm)
- [江西农业大学科学研究平台](https://www.jxau.edu.cn/kxyj.htm)
- [江西农业大学主页](https://www.jxau.edu.cn/)

### 江农特色知识域

| 优先级 | 知识域 | 产品化场景 | 证据要求 |
| --- | --- | --- | --- |
| P0 | 水稻/双季稻/南方粮油 | 品种、农时、病虫害、产量与栽培 | 江农科研成果 + 江西官方技术规范 |
| P0 | 家猪遗传育种与动物健康 | 种猪育种、饲养、动物营养、疫病风险 | 江农/农业农村部门/国家标准；不得输出诊疗处方 |
| P1 | 生物多样性、鄱阳湖流域生态与森林资源 | 生态保护、农业资源、乡村环境 | 生态环境/林草/江农科研来源，带空间与时间范围 |
| P1 | 果蔬采后、脐橙及质量安全 | 采后保鲜、分选、贮运、品质风险 | 江农果蔬平台、农业标准和地方产业资料 |
| P1 | 农业资源与环境 | 红壤、土壤肥力、水资源、面源污染 | 测定数据或官方/科研来源；不凭空给施肥量 |
| P1 | 现代农业装备与植保作业 | 旋耕机、植保无人机、作业安全 | 设备说明书、农机规范和江农装备研究 |
| P2 | 茶叶、中药材、天然产物与功能食品 | 江西特色产业与加工 | 先做来源注册和小规模评测，再进入默认回答 |

### 适配原则

1. 只有在知识库或官方来源明确支持时，才能说“江西农业大学团队/平台研究表明”；模型不得根据作物名称推断江农成果。
2. 用户询问家猪、生态、果蔬加工或农机时，仍必须遵守农业领域边界，但应优先匹配对应江农知识域，而不是只回退到水稻模板。
3. 江农特色是检索和内容优先级，不是对用户问题的强行改写；用户问江西之外地区时，先回答地区事实，再说明江农资料的适用范围。
4. 学校新闻、科研成果、政策和生产建议分开建索引，避免把新闻稿当作农技规范。

## 2. 当前基线与缺口

| 能力 | 当前实现 | 接入计划中的处理 |
| --- | --- | --- |
| Agent | LangChain/LangGraph 风格工具循环，支持 SSE | 保留循环，增加工具注册表、超时、重试和来源约束 |
| RAG | Chroma 本地持久化，支持本地哈希向量/远程 embedding | 先补元数据、混合检索、重排和离线评测，不急于迁移向量库 |
| 工具 | 农时、网页抓取、开放图片、日期等内嵌工具 | 统一为 MCP-compatible adapter，逐项替换 |
| 流式 | `status`、`delta`、`tool`、`ui`、`resources`、`done`、`error` | 增加 `source`、`trace`、`case` 事件，保持旧客户端兼容 |
| 前端 | 决策卡、知识上下文、资源卡、会话列表和状态栏 | 增加来源抽屉、数据新鲜度、人工升级和病例时间线 |
| 记忆 | SQLite 会话消息 | 增加 `case`、`case_event`、复查和用户反馈，不把聊天记录等同病例 |
| 缺口 | 无结构化场景上下文、县域数据治理、MCP 传输、评测集 | P0-P2 分阶段补齐 |

## 3. 产品边界与首批场景

### 3.1 产品定位

> 江西农业大学 CropWise：把田间观察转成有依据、能执行、可复查的农业决策。

### 3.2 P0 场景（首个可试用闭环）

| 场景 | 首批作物/地区 | 必须调用的数据 | 结果形态 |
| --- | --- | --- | --- |
| 病虫害辅助诊断 | 水稻、油菜、赣南脐橙；南昌/上饶/赣州 | 本地 RAG、开放图片、县域天气 | 五段式决策卡 + 2-3 个可能方向 + 复查节点 |
| 农时与天气 | 双季稻、油菜；县/区级 | CMA 或 Open-Meteo、农时知识库 | 日期任务、天气风险、错过窗口的替代方案 |
| 政策与技术核验 | 江西省/设区市/县级 | 农业农村部、江西农业农村部门、官方公告 | 已核验/待确认、原文链接、发布日期 |
| 施肥灌溉 | 水稻、蔬菜 | RAG、天气；后续土壤 | 依据、时机、限制条件；禁止无依据自动处方 |

### 3.3 非目标

- P0 不做自动确诊、自动下单农药、自动控制灌溉设备。
- 不抓取或存储未经授权的中国知网全文；论文只通过合法元数据、摘要或用户授权文件进入系统。
- 不把开放图片作为病害确诊证据；图片仅作识别参考并显示许可证/来源。
- 不因“有 MCP”就把所有外部服务接入生产，所有服务必须先通过数据源准入门槛。

### 4.3 数据源准入清单

每个服务必须在 `docs/data-source-registry.md`（后续建立）登记：

- 所有者、官网、API/下载入口、许可证和商业限制；
- 数据字段、空间粒度、时间粒度、更新时间、延迟和历史覆盖；

- 样例响应、字段版本、责任人、上线日期和回滚开关。

## 5. MCP 与内部工具统一契约

### 5.1 统一结果包

无论工具是本地函数、HTTP API 还是 MCP Server，都转换为以下结构；模型只能消费 `data`，前端只展示 `evidence` 和 `display` 白名单字段：

```json
{
  "ok": true,
  "tool": "weather_forecast",
  "data": {},
  "evidence": [{
    "title": "数据源名称",
    "url": "https://example.gov.cn/source",
    "publisher": "机构",
    "retrieved_at": "2026-08-09T10:00:00+08:00",
    "valid_at": "2026-08-09T08:00:00+08:00",
    "license": "公开资料"
  }],
  "display": {"label": "县域天气", "freshness": "2小时前"},
  "warnings": [],
  "trace_id": "trace_..."
}
```

失败也必须返回结构化结果：`ok=false`、`error_code`、用户可读 `message`、是否可重试和降级建议；禁止把 Python traceback 或 API key 传给模型/浏览器。

### 5.2 P0 工具目录

| 工具 | 输入 | 输出 | 失败降级 |
| --- | --- | --- | --- |
| `agri_knowledge_search` | query、crop、region、stage、top_k | 片段、来源、相关性、版本 | 只回答已确认内容并标记知识库暂无 |
| `weather_current` | county、lat/lon 可选 | 温度、降雨、风、预警、观测时间 | 使用最近可用观测并显示时间 |
| `weather_forecast` | county、日期范围 | 逐日预报、降雨概率、风险 | 返回“天气服务暂不可用”，不猜日期 |
| `crop_calendar` | crop、county、stage、target_date | 农时窗口、前置条件、替代方案 | 回退到本地 RAG 的通用窗口并标记 |
| `policy_search` | keyword、region、date_range | 官方标题、原文、发布日期、链接 | 只返回已检索官方入口 |
| `search_agri_resources` | query、kind、limit | 图片/文档 URL、来源、许可证 | 仅显示已验证链接 |
| `soil_query`（P2） | county/地块、指标、时间 | 土壤指标、采样时间、空间粒度 | 建议测土，不生成用量 |
| `case_review`（P1） | case_id、观察、照片引用 | 复查差异、下一步、升级信号 | 保留人工复核任务 |

### 5.3 传输与部署

1. P0：内嵌 adapter + 本地 HTTP 接口，保证当前单体项目可运行。
2. P1：稳定工具迁移为官方 MCP SDK 的 stdio/HTTP server，保留 adapter 兼容层。
3. P2：按数据源隔离 MCP 进程、密钥和限流；生产环境通过网关管理审计、超时和熔断。
4. MCP 不是数据治理替代品；每个工具仍需要来源、许可、版本和评测记录。

## 6. Agent 编排与回答协议

### 6.1 推荐流程

```text
用户问题
  -> 领域/安全分类
  -> 解析 scenario_context
  -> RAG 初检索
  -> 按场景选择 MCP 工具
  -> 工具结果校验/来源合并
  -> 生成五段式决策卡
  -> 证据、风险和复查检查器
  -> SSE 输出文本/UI/来源
  -> 保存 case 与反馈
```

### 6.2 结构化请求

在兼容旧 `message` 的同时增加：

```json
{
  "message": "小麦叶片出现黄色条纹",
  "thread_id": "thread_...",
  "scenario_context": {
    "scenario": "diagnosis",
    "crop": "小麦",
    "region": "江西南昌",
    "stage": "返青期",
    "observations": ["黄色条纹"],
    "impact": "待补充"
  }
}
```

前端场景表单只负责采集和兼容回退；场景分类、必填字段、风险规则必须由后端复核。

### 6.3 决策卡质量闸门

- 无地区/生育期/影响范围时显示“待补充”，不能伪造；
- 农药/肥料答案必须有登记/说明书/安全间隔提示和来源日期；
- 气象、农时、政策必须带 `valid_at`/发布日期；
- 图片只作为识别参考，不得把相似图片写成确诊；
- 低召回或冲突来源时降低结论强度并触发农技人员升级。

## 7. RAG 数据工程

### 阶段 1：当前 Chroma 增强（P0）

- 文档元数据：作物、病虫害、地区、县域、品种、生育期、来源机构、发布日期、有效期、许可证；
- 文本清洗：标题/章节/表格/单位保留，按“规范条款/症状/措施/禁忌”切块；
- 检索：向量 + BM25/关键词混合，按地区/作物/时间过滤；
- 召回：top-k + 去重 + 简单重排，输出引用片段而非只给匹配度；
- 评测：每次知识库变更跑固定问题集，保存 recall@k、MRR、引用覆盖率。

### 阶段 2：专题知识包（P1）

首批建立四个版本化知识包：`jiangxi-rice`、`jiangxi-rapeseed`、`gannan-citrus`、`jiangxi-policy`。每包包含来源清单、更新时间、负责人和回滚版本。

### 阶段 3：混合/迁移评估（P2）

只有在文档规模、并发或过滤需求超过 Chroma 当前边界时，才用同一评测集比较 pgvector、Milvus、RAGFlow 或 FastGPT；迁移不得以“框架更大”作为验收条件。

## 8. 前端与用户体验

- 用户默认看到“正在匹配知识库/正在核对天气/已参考 3 个来源”，不显示函数名、JSON、trace 或模型内部思考；
- 来源抽屉展示机构、标题、发布日期、有效期、许可证、访问链接和“为什么引用”；
- 外部资料明确标记“补充参考”，本地审核知识标记“农业知识库依据”；
- 资源卡显示图片用途和版权，不把开放图片伪装成诊断证据；
- 决策卡支持“补充现场信息”“提交复查”“转交农技人员”；
- 断网/限额/低置信度状态要有可恢复操作，不能只显示空白卡片。

## 9. 安全、合规与运维

### 安全

- API key 只存在后端 secret；前端不接触第三方凭据；
- 所有外部 URL 做 HTTPS、域名白名单、重定向复核、响应大小/类型限制，防 SSRF；
- MCP 工具按最小权限、独立超时、限流、熔断、缓存和审计；
- 模型输出只能映射到白名单 UI 组件，不能执行 HTML、JS、SQL 或动态工具名。

### 数据与隐私

- 默认保存县/区级区域，不强制精确坐标；
- 图片、病例、复查和人工升级支持保留期限及删除；
- 转交农技人员前显示将共享的字段；
- 政策、农药、肥料和病例日志保存来源版本、检索结果和模型版本。

### 可观测性

记录 `trace_id`、`thread_id`、`case_id`、tool、provider、耗时、缓存命中、错误码、token/cost、召回文档 ID；日志脱敏，前端只显示用户可理解摘要。

## 10. 评测指标与验收门槛

### 离线集

首批至少 120 条人工标注问题：诊断 40、施肥灌溉 25、农时天气 25、政策 20、越界/安全 10。每题包含场景、作物、地区、生育期、期望来源和禁止结论。

### 指标

| 指标 | P0 门槛 | 说明 |
| --- | --- | --- |
| 农业领域越界率 | < 1% | 数学/编程等必须拒答 |
| 结构化场景解析准确率 | >= 90% | 必填字段与场景一致 |
| top-5 证据相关性 | >= 80% | 人工标注相关/不相关 |
| 引用覆盖率 | >= 85% | 关键判断有对应证据 |
| 五段式完整率 | >= 95% | 缺失信息可明确待补充 |
| 农药/肥料安全提醒覆盖率 | 100% | 相关题不可缺失 |
| MCP 成功率 | >= 98% | 排除上游明确 4xx |
| SSE 完整结束率 | >= 99% | 有 `done` 或可解释 `error` |

## 11. 90 天里程碑

### 第 0-1 周：契约和决策冻结

- 定稿 `ToolResult`、`scenario_context`、来源字段和事件兼容策略；
- 建立数据源注册表、许可证清单、120 条评测集骨架；
- 交付：API schema、MCP adapter 模板、风险规则清单。

### 第 2-3 周：P0 数据与 RAG

- 整理江西水稻/油菜/脐橙/政策知识包；
- 增加元数据过滤、混合检索、来源抽屉数据；
- 交付：离线检索报告、知识包版本和回滚脚本。

### 第 4-5 周：气象/农时/政策工具

- 接入一个可稳定调用的气象 provider；
- 实现 `weather_current`、`weather_forecast`、`crop_calendar`、`policy_search` adapter；
- 交付：县域样例、超时/缓存/降级测试。

### 第 6-7 周：标准 MCP 化

- 将经过评测的工具迁移为 MCP stdio/HTTP server；
- Agent 同时支持内嵌 adapter 和 MCP endpoint；
- 交付：本地启动配置、工具版本锁定、审计日志。

### 第 8-9 周：病例与复查

- `cases`、`case_events`、复查、反馈和农技升级 API；
- 前端增加时间线和转交摘要；
- 交付：端到端诊断/复查演示。

### 第 10-11 周：图片与空间能力

- 图片辅助鉴别、来源许可证和人工复核；
- 评估土壤/遥感数据，不在无授权时存精确地块坐标；
- 交付：误判边界、低置信度和失败降级测试。

### 第 12-13 周：试点与决策

- 江农师生、农技人员、种植户小范围试用；
- 对比自由问答与场景入口的完成率、引用点击率、复查率；
- 交付：试点报告、P1/P2 优先级和是否迁移 RAGFlow/Milvus 的决策。

## 12. 返工防线

在下面条件未满足前，不进入下一阶段：

1. 没有样例响应、许可证和失败降级，不接入新数据源；
2. 没有离线评测基线，不更换 embedding、向量库或 RAG 框架；
3. 没有结构化来源，不把外部搜索结果写入决策卡；
4. 没有人工复核边界，不上线农药、肥料或病害自动处方；
5. 没有移动端、断网、超时和重复请求测试，不扩大 MCP 工具数量。

## 13. 需要产品确认的决策

以下是会显著影响数据模型和工期的选择，默认值为推荐方案：

| 决策 | 推荐默认 | 影响 |
| --- | --- | --- |
| 首批区域 | 江西省全省县/区级，重点南昌/上饶/赣州 | 决定气象站映射、农时和政策筛选 |
| 首批作物 | 水稻、油菜、赣南脐橙、蔬菜 | 决定知识包和图片评测集 |
| 气象服务 | 先 Open-Meteo/公开数据 PoC，再评估 CMA 正式授权 | 决定实时性、额度和合规 |
| MCP 形态 | P0 内嵌 adapter，P1 标准 MCP HTTP/stdio | 决定部署复杂度和可移植性 |
| RAG 基础设施 | 继续 Chroma，达标后再比较 pgvector/Milvus/RAGFlow | 避免无指标迁移 |
| 病害图片 | 参考图 + 人工复核，不自动确诊 | 决定安全责任和模型评测 |
| 病例隐私 | 县/区级默认，精确坐标 opt-in | 决定数据库字段和共享边界 |
| 试点用户 | 江农师生 + 农技人员 + 少量种植户 | 决定反馈、案例和验收权重 |
