# CropWise Agent 记忆契约

## 目标

“相关”由当前任务决定，“相似”只用于候选召回。RAG 知识证据永远不写入用户记忆。

## 分层

| 层 | 生命周期 | 默认用途 |
| --- | --- | --- |
| `thread` | 当前会话 | 最近 8 条消息，保持连续对话 |
| `task` | 默认 14 天 | 当前作物、地区、生育期、症状、目标和约束 |
| `user` | 用户明确确认后长期保留 | 稳定地区、长期作物、明确偏好 |
| `knowledge_evidence` | 单次回答 | RAG 检索结果，不进入记忆表 |

## 相关性规则

1. 当前消息中的新事实优先于旧事实。
2. 当前任务约束 > 当前任务目标 > 用户长期记忆 > 普通历史事实。
3. 过期、删除、归档记忆默认不注入。
4. 同一会话同一事实维度（作物/地区/生育期）出现新值时，旧值归档。
5. 低于 `0.32` 的相关性门槛只进入“相似但未使用”，不得进入模型提示词。

## 被动提取与主动提取

- 被动提取：从用户明确陈述中抽取作物、地区、生育期、目标或约束，标记为 `extraction_mode=passive`、`verification_status=pending`；它可以服务当前任务，但不会自动升级为长期用户记忆。
- 主动提取：当问题涉及诊断、防治、施肥、播种等决策且缺少地区、生育期或症状范围时，只提出最多 2 个关键追问；不为了填表而连续盘问。
- 长期记忆：必须通过用户确认接口，确认后标记 `extraction_mode=active`、`verification_status=confirmed`，并清除默认过期时间。
- 业务系统/权威文档来源可以直接进入证据层，但仍必须带来源和时间，不能与用户口述混为一谈。

## SSE 事件

- `memory-candidate`：显式提取、待用户确认的任务记忆。
- `memory-action`：主动提取产生的关键追问。
- `memory-organized`：达到数量或冲突临界点后的整理结果。
- `memory`：本轮 `used` 与 `skipped` 记忆及相关性分数。

前端默认折叠展示“本轮记忆依据”，避免把内部检索过程伪装成回答内容。

## 农业场景检索策略

- 普通种植/病虫害问题：向量候选 + 中文词项命中（`hybrid`）。
- 江西农时、播期、生育期、近期天气：在混合召回上加入时间字段和时效标签（`hybrid-temporal`）。
- 农业政策、标准、登记信息、产品型号：在混合召回上加入来源与元数据过滤（`hybrid-metadata`）。
- `GET /knowledge-base/search` 会返回实际策略及向量/词项/元数据分数，便于 RAG 验收。

## 管理 API

- `GET /memory/{thread_id}`：读取会话相关记忆。
- `GET /memory/user/{user_id}`：读取已确认的用户记忆。
- `POST /memory/{memory_id}/confirm`：把任务记忆升级为长期用户记忆。
- `DELETE /memory/{memory_id}`：软删除记忆。
- `POST /memory/整理?thread_id=...`：归档过期记忆并返回摘要。

## 验收标准

- 早餐偏好等语义相似但与农业任务无关的历史不进入农业回答。
- 新目标能覆盖旧偏好，冲突事实不会静默合并。
- 跨会话读取按 `user_id` 隔离；删除后不再注入。
- RAG 上下文只出现在知识证据区，不生成 `agent_memories` 记录。
- `test_memory_relevance.py`、领域约束、SSE 契约与前端生产构建全部通过。
