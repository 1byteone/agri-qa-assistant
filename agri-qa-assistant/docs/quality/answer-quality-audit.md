# CropWise 回答质量与前端可见性验收标准

本审计从用户视角验证“回答是否可信、是否知道依据、是否知道回答是否完成”。测试不依赖在线大模型，优先约束可确定的服务端协议，再用真实 SSE 做运行态复核。

## 验收矩阵

| 维度 | 必须满足 | 自动化证据 |
| --- | --- | --- |
| 农业边界 | 数学、编程和通用问题在检索与模型前被拦截，不生成越界内容 | `test_domain_guard.py`、`test_stream_contract.py` |
| RAG 证据 | 相关性低于阈值或非 A 级来源不得显示为可引用依据；高风险具体剂量必须降级为原则或要求核验 | `test_answer_quality_audit.py`、`test_retrieval_strategy.py` |
| 决策卡 | 现场信息缺失时状态为“待补充现场信息”，不得误报“信息完整” | `test_answer_quality_audit.py` |
| 日期语义 | 当前日期来自服务端时钟；用户给出的日期标为评估日期，不得称为当前日期 | `test_mcp_temporal.py`、真实 SSE |
| 回答模式 | 专业模式输出决策卡；简要模式不输出五段式标题并受长度上限约束 | `test_models.py`、`test_mcp_temporal.py` |
| 工具透明度 | 工具运行与完成均有名称、来源、成功标志、错误码和耗时；工具协议不进入正文 | `test_stream_contract.py`、真实 SSE |
| Markdown | 常见的 `*标题**`、孤立 `-` 和工具标记在持久化及渲染前清洗 | `test_answer_quality_audit.py` |
| 流式状态 | 正常完成、备用回答、拦截和错误分别标记；连接/模型失败不得伪装为普通完成 | `test_answer_quality_audit.py`、前端构建 |

## 用户回答分层

主回答只承担决策：**结论 → 现场摘要 → 优先判断 → 现在做什么 → 风险边界 → 复查节点**。RAG 片段、相关性、来源、工具调用和检索策略属于可追溯依据层，默认收起，不得混入主回答或污染行动卡。

助手消息持久化 `answer_mode`、`completion_status` 和 `decision_card`，历史恢复优先使用这些结构化字段；旧消息没有扩展字段时，服务端按同一规则回填，保证首次回答与刷新后的布局一致。

## 交付门槛

- 后端审计用例和既有回归用例全部通过。
- `npm run build` 通过且 TypeScript 无错误。
- `/health` 返回 `healthy`，知识库数量可读取。
- SSE 的最后一个 `done` 必须包含 `completion_status`；工具完成事件必须包含 `ok`、`source`、`duration_ms` 和 `error_code` 字段（成功时 `error_code` 可为 `null`）。
- 任何低相关片段只能作为背景显示，必须出现“弱证据 · 不作结论依据”。

## 人工抽检建议

每次发布至少抽检四个问题：水稻稻飞虱防治、江西早稻农时、土壤改良、非农业编程问题。分别检查结论、证据标签、模式呈现、工具状态和完成状态；涉及农药/肥料的数值必须点击来源或转为官方核验提示。

## 已知边界

本项目的内嵌工具层是 MCP-compatible adapter，不等同于已连接外部 MCP Server；外部资料和图片仍需网络可用性与来源页面二次核验。模型输出仍需持续做离线回归和人工抽检，不能把相似度分数当成事实正确率。
